# 自营数据服务操作流程

当前优先完善运营者代客户下载、处理和交付的体验。一个客户订单可对应一个或多个批次；批次名称建议包含客户代号、产品与时间范围，便于搜索和交付核对。

## 提交与跟进

1. 在任务包页面确认处理包版本及输入要求，再新建任务。批量数据可使用现有 CSV 导入和逐行校验。
2. 明确目标接收端，检查工作节点、接收端是否在线、已启用且有足够磁盘空间。提交前的小批次试跑应验证输入、输出内容及处理参数。
3. 在批次进度页查看处理建议。全部已交付、暂停、失败、停止和等待接收端拉取会显示不同说明；上传完成仍属于待交付。
4. 使用“查看失败”“核对已停止”“查看待交付”直接筛选明细。数据粒 ID 搜索支持不区分大小写的字面子串；百分号和下划线按普通字符处理。
5. 暂停只阻止新分发，已领取任务继续完成。普通“重试失败”只重置 `failed`；`blacklisted` 可能包含重试耗尽或主动取消，需单独核对后重试，或在更多操作中确认批量重新处理。
6. 产物拉取重试耗尽时，先修复接收端、网络、磁盘或源产物问题，再使用“恢复交付”。恢复不会重新运行下载和处理，只重新开放产物拉取。

历史记录没有独立标记主动取消的原因，因此不能可靠地区分既有 `blacklisted` 数据中哪些是主动取消。界面不把它们自动纳入普通失败重试。旧客户端直接调用 `/retry-failed` 且不传参数仍保留原行为；新界面显式传 `include_blacklisted=false`。

## 导出与验收

批次详情的“导出交付报告”下载 UTF-8 CSV，可用表格软件打开。内容包括生成时间、批次、处理包、累计数量、各阶段数量，以及仍保留产物的路径、字节数、SHA-256、接收端和确认时间。未确认接收的产物标为待交付。

报告不包含下载凭证、签名访问地址、输入源地址或执行日志；文本会处理表格公式前缀。后端分块读取清单，不把整个批次的对象载入内存。

**累计统计不等于完整历史明细。** 默认 `SATHOP_RETAIN_DELETED_DAYS=1`，完成后的运行明细会按保留策略清理，累计交付数继续保留。分页使用实际保留行数。自 v1.0.22 起，接收成功会在同一事务内记录长期交付台账，批次报告合并台账与当前产物且不重复计数。升级时会补录仍存在的接收确认；升级前已清理的文件名和哈希无法补回。

运行中的报告反映导出期间的状态，并非冻结验收单。“已交付”表示接收端确认成功；实际交付还应核对接收端文件、校验值以及客户要求的产品内容。对外提交报告前，应完成接收端文件验收。

## 长期交付台账

从侧栏“交付台账”进入，或在批次详情点击“查看交付台账”。可搜索批次名称、数据粒、产物路径和接收端，按批次 ID、起止日期筛选，查看筛选范围内的文件数、体积、数据粒数和批次数。日期按当前设备时区解释，结束日期包含当天；报告时间统一为 UTC。

“导出筛选结果”导出所有匹配记录，不仅是当前页。台账只含已经确认的文件，保留任务包版本、产物路径、字节数、SHA-256、首次确认时间和接收端，不含访问地址或凭证。重复确认不会覆盖首次凭据，确认后的迟到失败报告不会重置交付状态。

台账与运行明细分开保存，自动清理和手动删除批次均不删除台账。文件数与数据粒数是不同统计单位，一个数据粒可以有多个产物。删除批次后仍能检索和导出交付记录。台账目前不设自动过期，应纳入 PostgreSQL 常规备份并监控长期容量；它并非防篡改审计或接收端文件备份。

## 任务模板

在“新建任务”顶部选择模板并点击“套用配置”，再填写本次批次名称、输入表格和下载凭证。更换任务包会重建输入表格；表单已有内容时会先提醒。模板固定处理包版本，不会自动切换到新版本；依赖已被删除时会提示先修复配置。

可展开“将当前配置保存为模板”，为当前任务包与接收端命名并保存。模板保存在服务器，重启或更换浏览器后仍可使用。可另存新模板、更新原模板或删除模板；均不影响已提交批次。同名模板会提示冲突。

模板不接受下载凭证和输入数据。高级环境变量默认不保存，需要明确勾选；勾选前请确认内容没有密码或令牌。模板不能替代提交前的节点在线、磁盘与小批次试跑检查。

## 发布与恢复

生产发布使用现有 minisign 签名包；先备份 PostgreSQL、Compose 配置和旧版本目录，验证签名并预装新版本，再切换 `.pending-version` 和重启调度端。验证 `/api/health`、前端资源、原有批次计数和新增只读接口。

以非 root 用户运行时，镜像内预热依赖缓存可能不可写。新版 entrypoint 会改用 `/app/repo/.uv-cache`；仍使用旧运行镜像的部署可在 orchestrator 的 Compose environment 中显式设置 `UV_CACHE_DIR: /app/repo/.uv-cache`。

v1.0.22 新增 `delivery_records`、`task_templates` 两张独立表及索引，启动时补录已有确认记录，不改写运行任务。升级前备份数据库。回退 v1.0.21 会保留新表，但旧代码不会继续记账或展示模板；如果回退期间旧版本已清理运行明细，这段记录之后无法补录，因此回退应保持业务暂停。不要为代码回退恢复旧数据库覆盖新记录。
