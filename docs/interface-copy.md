# 界面文案

SatHop 面向负责数据处理与交付的运营人员。文案应帮助用户识别状态、决定操作和核对结果。

- 使用事实描述，避免“极速”“永不”“一键搞定”等未经验证的承诺。
- 页面说明只交代用途；实现细节放在技术文档或必要的高级设置中。
- 操作按钮使用明确动词，如“新建批次”“恢复交付”“删除记录”。
- 提交请求与完成操作分开表述。异步操作说明生效时间，不提前宣告完成。
- 删除、重新处理、重新分配等确认框应写明范围、数据影响及是否可恢复。
- 加载中、读取失败、无数据是不同状态。未获取数据时，不显示“正常”或“空闲”。

统一用语：

| 含义 | 界面用语 |
| --- | --- |
| 一组输入数据与执行配置 | 批次；新建批次 |
| 批次中的单个处理单元 | 数据粒 |
| orchestrator | 调度服务 |
| worker / receiver | 工作节点 / 接收端 |
| uploaded，尚未收到接收确认 | 待交付 |
| blacklisted，含重试耗尽与主动取消 | 已停止 |
| 产物拉取重试耗尽 | 交付受阻 |
| 停止或恢复分配新任务 | 暂停调度 / 恢复调度 |
| 收回节点持有的未完成任务 | 重新分配任务 |
| fast 上报模式 | 精简上报 |

界面名称不改变 API 字段或枚举。配置项、文件格式、校验算法等技术名称，在用户需要配置或核对时保留。
