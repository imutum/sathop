# State machine: Python single-source, TS hand-mirrored

`src/sathop/shared/state_machine.py` is the single source of truth for the granule state machine on the Python side: `STATE_TABLE` declares every state's flags (`leased / in_flight / non_terminal / active / cancellable / retryable`), predecessor, and stage-closer; backend constants (`LEASED_STATES`, `IN_FLIGHT_STATES`, `CANCELLABLE_STATES`, …) are derived from it.

The frontend (`frontend/src/apiTypes.ts`) still defines `GranuleState`, `IN_FLIGHT_STATES`, and `STATE_ORDER` as hand-maintained string literals. We deliberately did not introduce a Python→TS code-generation step: the surface is one enum + two arrays, the cost of one extra build dependency and a generated file in source control exceeded the drift risk for a 1-orchestrator project. The trade-off is that adding/removing a state requires touching two files in lockstep — backend tests still pass when TS drifts, so reviewers must catch it. If the drift ever bites (a TS check missing a real backend state in production), revisit by generating `frontend/src/generatedStates.ts` from `state_machine.py` at build time, or by switching to an OpenAPI schema export.
